Guides

Webhooks

Push execution and checkpoint events into your own systems instead of polling. Signed, retried and ordered per execution.

Setting up an endpoint

Add the endpoint under Providers → Outbound webhooks, pick the events and copy the signing secret. Endpoints must be HTTPS and answer within 5 seconds.

Events

EventFires when
execution.startedA worker picks the execution up
execution.completedExecution reached done
execution.failedExecution reached failed, after retries
execution.cancelledCancelled by a person or by policy
stage.failedA stage failed, even if the execution recovers
checkpoint.requestedA boundary parked an execution
checkpoint.decidedSomeone accepted or declined
checkpoint.expiredTTL elapsed with no decision
budget.thresholdWorkspace spend crossed 80%
budget.cap_reachedNew executions parked at the cap

Verifying the signature

Each delivery carries X-Nalvo-Signature — an HMAC-SHA256 of the raw body with your endpoint secret — and X-Nalvo-Timestamp. Verify both, and reject anything older than five minutes.

verify.js
import crypto from "node:crypto";

function verify(rawBody, headers, secret) {
  const ts = headers["x-nalvo-timestamp"];
  if (Math.abs(Date.now() / 1000 - Number(ts)) > 300) return false;

  const expected = crypto
    .createHmac("sha256", secret)
    .update(ts + "." + rawBody)
    .digest("hex");

  return crypto.timingSafeEqual(
    Buffer.from(expected),
    Buffer.from(headers["x-nalvo-signature"])
  );
}
Use the raw body

Verify before any JSON middleware parses and re-serialises the request. Re-serialised JSON produces a different byte string and the signature will never match.

Retries and ordering

  • Any non-2xx or a timeout is retried with exponential backoff: 10s, 1m, 5m, 30m, 2h, 6h
  • After six failures the endpoint is marked unhealthy and shown in the console
  • Events for the same execution are delivered in order; across executions they are not
  • Deliveries are at-least-once — dedupe on event.id

Testing locally

shell
nalvo webhooks listen --forward http://localhost:3000/hooks
# → tunnelling acme-ops events to localhost:3000

nalvo webhooks send execution.failed --execution 8289
# → sent test event evt_test_44a1

Practices

  • Answer fast, work later. Return 200 immediately and process on a queue — the 5-second budget is enforced.
  • Treat events as hints, not truth. Fetch the execution from the API when you need authoritative state.
  • Do not resolve checkpoints in a webhook. Decisions belong in the workspace or through the API; a webhook is a notification.
