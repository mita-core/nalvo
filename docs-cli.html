Reference

CLI

Deploy workers from CI, follow executions from a terminal and keep definitions in git where they belong.

Install

shell
brew install nalvo/tap/nalvo # macOS
npm install -g @nalvo/cli         # anywhere node runs

nalvo auth login                  # opens a browser
nalvo auth status
# → acme-ops · jordan@acme.io · scope: deploy

In CI, skip the browser and set NALVO_KEY with a deploy-scoped key.

Workers

shell
nalvo workers list
nalvo workers show invoice-parser-v2
nalvo deploy invoice-parser-v2.yaml
nalvo deploy ./workers --all --dry-run
nalvo workers pause contract-renewal-bot
nalvo workers rollback invoice-parser-v2 --to 1.8.2
FlagEffect
--dry-runValidate and print the diff without deploying
--waitBlock until smoke tests finish, non-zero exit on failure
--env stagingTarget another workspace
--jsonMachine-readable output for scripts

Executions

shell
nalvo executions list --status failed --since 24h
nalvo executions start invoice-parser-v2 --input '{"batch":"2024-08-03"}'
nalvo executions show 8290
nalvo executions tail 8290       # live stage output
nalvo executions cancel 8290
nalvo executions export --since 30d --format csv > executions.csv

Decision checkpoints

shell
nalvo checkpoints list --pending
nalvo checkpoints show chk_8291_001
nalvo checkpoints decide chk_8291_001 --accept --note "Legal reviewed"
Do not turn a checkpoint into a cron job

The command exists for break-glass situations and is recorded in the decision record with the key that used it. If a decision can be automated, put it in the worker policy instead.

In CI

.github/workflows/deploy.yml
name: deploy-workers
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm install -g @nalvo/cli
      - run: nalvo deploy ./workers --all --wait
        env:
          NALVO_KEY: ${{ secrets.NALVO_DEPLOY_KEY }}

Configuration

The CLI reads ~/.nalvo/config.toml, overridden by environment variables and then by flags.

~/.nalvo/config.toml
[default]
workspace = "acme-ops"
region    = "us-east-1"
output    = "table"

[staging]
workspace = "acme-ops-staging"
