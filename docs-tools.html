Guides

Connections

A connection is any outside capability a worker can reach. Register it once with a schema and scope, then revoke access from one place.

Registering a connection

A connection manifest declares the name, parameters and allowed destination. Deploy it like a worker definition.

pdf_exporter.json
{
  "name": "pdf_exporter",
  "version": "2.1.4",
  "description": "Generate PDF reports from structured data.",
  "lane": "active",
  "endpoint": "https://tools.acme.io/pdf",
  "timeout_ms": 30000,
  "parameters": {
    "template":     { "type": "string", "required": true },
    "orientation":  { "type": "enum", "values": ["portrait", "landscape"] },
    "header_image": { "type": "url" }
  }
}

Granting access

Registration does not grant anything. A worker may use a connection only when it appears in its definition and the registry contains a matching grant. Anything else is refused and recorded as a policy violation.

shell
nalvo connections grant pdf_exporter --worker invoice-parser-v2 --scope write
nalvo connections revoke legacy_ftp --all
# → revoked from 3 workers, effective immediately
Revocation is instant and global

Revoking does not wait for a redeploy. Live executions fail their next call with connection_revoked, so park affected workers first when the connection is on a hot path.

Lanes

LaneBehaviour
activeNormal. Counted in SLAs and health metrics.
betaCallable, flagged in the console, excluded from SLA calculations.
deprecatedStill works until removal_date; every call emits a warning into the execution events.

Using a connection

worker.js
const report = await nalvo.connections.call(execution.id, "pdf_exporter", {
  template: "vendor-summary",
  orientation: "portrait"
});

// the call is recorded on the current stage:
// latency, status code, bytes in/out, cost

Calls made through nalvo.connections.call are attributed to the enclosing stage automatically, which fills the latency and error-rate figures on the Connections page.

Providers

Providers hold managed credentials for systems such as Slack, Salesforce, S3, Postgres and PagerDuty. Nalvo stores only an encrypted refresh token, never the password.

  • OAuth connections are approved by a workspace admin, once
  • Scopes can be narrowed per worker — read-only for most, write for a named few
  • An expired token surfaces on the Providers page before executions start failing in bulk
