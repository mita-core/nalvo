Decision checkpoints

Pause an execution at the exact moment human judgement matters, with enough evidence to answer without opening another system.

Declaring a checkpoint

Checkpoints come from two places. Declarative checkpoints live in the worker definition and are enforced by the runtime, outside your application code:

worker.yaml
boundaries:
  checkpoint_above: "$50000"
  checkpoint_connections:
    - salesforce_api
    - etl_processor
  checkpoint_data:
    - pii
    - financial

Imperative ones are raised from code when the condition is something only your logic knows:

worker.js
const decision = await nalvo.checkpoints.request(execution.id, {
  title: "Review contract amendment",
  summary: "MSA-2023-4402 extends term through Q1 2025.",
  risk: "low",
  assignee: "legal",
  ttl: 14400,
  diff: {
    file: "MSA-2023-4402-A1.md",
    hunks: [
      { line: 15, remove: "Effective through Sep 30, 2024",
                   add:    "Effective through Mar 31, 2025" }
    ]
  }
});

Give it a real diff

The single biggest factor in decision speed is whether the approver can see what changes without opening anything else. A diff of the actual artifact — contract text, price rows, SQL statements — turns a five-minute investigation into a five-second read.

Rule of thumb

If the approver has to ask “what does this actually do”, the request was missing a diff. Median decision time across workspaces that send diffs is 42 seconds; without one it is over eleven minutes.

Risk tiers and routing

Every request carries a tier. The tier decides who is asked, how many people must agree, and how long before it escalates.

TierApproversTTLOn expiry
lowAny member of the owning group8hEscalate to group lead
mediumTwo members of the owning group4hEscalate to admins
highNamed approvers only1hPage on-call, then cancel

Reading the response

decision object
{
  "id": "chk_8291_001",
  "status": "accepted",        // accepted | declined | expired
  "by": "jordan@acme.io",
  "at": "2024-08-03T09:34:12Z",
  "note": "Legal reviewed the SLA change.",
  "waited_ms": 1932000
}

Handle all three states. An expired checkpoint grants nothing — treat it like a decline unless your policy explicitly says otherwise.

Patterns that work

  • Checkpoint the write, not the read. Let the worker gather and prepare freely; ask only before the irreversible stage.
  • One request per decision. Bundling twelve price changes into one checkpoint encourages a blanket answer.
  • Send the blast radius. “1,240 SKUs, est. +$18K/mo” is a decision. “Apply pricing update” is not.
  • Fail closed. If the checkpoint service is unreachable, park the execution — never proceed on a timeout.

What lands in the decision record

Every request and response is appended to the workspace evidence chain: who asked, what was shown, who answered, when and from where. See Security & compliance.
