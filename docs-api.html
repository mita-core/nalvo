Reference

REST API

Base URL https://api.nalvo.dev/v1. JSON in, JSON out, bearer auth. Every workspace action is available through these endpoints.

Authentication

Send the API key as a bearer token. Keys are workspace-scoped and carry one of four scopes: read, write, deploy, sandbox.

shell
curl https://api.nalvo.dev/v1/executions \
  -H "Authorization: Bearer $NALVO_KEY"

Executions

POST /v1/executions

Create and queue an execution.

request
{
  "worker": "invoice-parser-v2",
  "trigger": "api call",
  "input": { "batch": "2024-08-03" },
  "idempotency_key": "inv-20240803"
}
201 response
{
  "id": 8290,
  "status": "queued",
  "worker": "invoice-parser-v2",
  "version": "1.8.3",
  "created_at": "2024-08-03T09:00:00Z",
  "url": "https://app.nalvo.dev/acme-ops/executions/8290"
}
GET /v1/executions

List executions, newest first. Cursor paginated.

Query paramTypeNotes
workerstringFilter by registry name
statusenumqueued, running, waiting, done, failed, cancelled
sinceISO 8601Created at or after
limitint1–200, default 50
cursorstringFrom next_cursor
GET /v1/executions/:id

One execution with its stages, cost breakdown and checkpoint history.

POST /v1/executions/:id/cancel

Abort the current stage and mark the execution cancelled. Partial artifacts are kept.

Stages

POST /v1/executions/:id/stages

Record a stage. Send it when work starts and patch it when it ends, or send it once on completion.

request
{
  "name": "extract_entities",
  "connection": "pdf_parser",
  "status": "done",
  "duration_ms": 2400,
  "tokens": 847
}

Decision checkpoints

POST /v1/executions/:id/checkpoints

Raise a decision request. The call returns with status: "pending" — poll, subscribe to the webhook, or use the SDK helper that waits for a response.

GET /v1/checkpoints

List checkpoints across the workspace. Filter with status=pending to build your own queue.

POST /v1/checkpoints/:id/decide
request
{ "decision": "accepted", "note": "Legal reviewed the SLA change." }

Workers

GET /v1/workers
POST /v1/workers
POST /v1/workers/:name/deploy
POST /v1/workers/:name/pause

Deploying requires a key with the deploy scope. The body is the worker definition — the same YAML the CLI sends, as JSON.

Errors

Errors are JSON with a stable code. Never match on the message.

422 response
{
  "error": {
    "code": "worker_not_deployed",
    "message": "invoice-parser-v3 has no deployed version",
    "request_id": "req_9c21f0a4"
  }
}
StatusCodeMeaning
401invalid_keyMissing, malformed or revoked key
403insufficient_scopeKey lacks the required scope
404not_foundObject does not exist in this workspace
409duplicate_idempotency_keyAn execution with that key already exists
422worker_not_deployedNo deployed version to execute
429rate_limitedBack off using Retry-After
503spend_cap_reachedWorkspace paused at its cap

Rate limits

  • 600 requests per minute per key on Scale, 60 on Starter
  • Burst of 1,200 over 10 seconds
  • Request bodies up to 2 MB
  • Every response carries X-RateLimit-Remaining and X-Request-Id

Versioning

The version is in the path. Breaking changes ship as /v2 with at least six months of overlap; additive fields can appear in /v1 at any time, so parse defensively.
