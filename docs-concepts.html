Getting started

Core concepts

Five objects describe the Nalvo evidence model. The API and workspace are simply two views of the same record.

Worker

A named, versioned definition of autonomous work: the model it uses, the connections it may call, its timeout, retry policy and boundaries. Workers live in the registry and ship like code, with an explicit active version and one-action rollback.

FieldMeaning
nameRegistry key. Lowercase with dashes, unique per workspace.
versionSemver. A deploy always creates a new one.
connectionsAllow-list. Every other external call is rejected at runtime.
boundariesSpend limits, checkpoint thresholds and PII redaction.
ownerAccountable group. Determines checkpoint routing.

Execution

One attempt by a worker. An execution has a trigger, an input payload, an ordered sequence of stages and exactly one terminal state.

execution states
queued  →  running  →  done
                    ↘  waiting  →  running  →  done
                    ↘  failed
                    ↘  cancelled
  • queued — accepted, waiting for a worker
  • running — a worker is executing steps
  • waiting — parked at a human checkpoint; not consuming a worker
  • done / failed / cancelled — terminal, never reopened. A retry creates a linked execution.
Waiting is free

An execution parked at a checkpoint releases its worker and costs nothing while it waits. A four-hour review window never becomes four hours of compute.

Stage

The unit inside an execution: a name, duration, model usage and optionally one connection call. Stages turn a vague failure into a precise fact, such as create_user_record timing out against salesforce_api after three retries.

Connection

An external capability registered once with a JSON schema, then granted to specific workers. The registry makes immediate revocation possible without redeploying workflow code.

Connections carry a lifecycle state — active, beta or deprecated. Deprecated connections continue until their removal date and warn on every call.

Checkpoint

A decision request raised by an execution. It carries the proposed change, impact tier, reviewer group and TTL. Resolving it resumes or cancels work; expiry escalates to the next group.

Risk tierTypical routingDefault TTL
lowOwning group, any member8 hours
mediumOwning group, two reviewers4 hours
highNamed reviewers, escalates to admins1 hour

Workspace

The boundary for everything above: workers, executions, connections, members, spending limits and evidence chain. A workspace pins one region. Most companies use production and staging with the same versioned definitions.
