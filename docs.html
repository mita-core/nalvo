What Nalvo adds

Nalvo is the evidence and intervention layer beside your autonomous framework. Keep the LangChain graph, custom loop or scheduled script you already run; add live execution state, policy checkpoints, scoped connections, spending boundaries and a verifiable decision history around it.

Three records form the core of the system:

  • Executions — one attempt by a worker, from trigger to terminal state.
  • Stages — ordered units inside an execution with timing, model usage and optional connection calls.
  • Checkpoints — human decisions preserved with their policy and evidence.

The mental model

Your code opens an execution, reports each stage and requests a checkpoint when a policy boundary is reached. Nalvo preserves the record, enforces the boundary and exposes the current state to the accountable team.

the shape of it
// 1 — open an execution
const execution = await nalvo.executions.open({ worker: "invoice-parser-v2", input });

// 2 — report stages as they happen
await nalvo.stages.record(execution.id, { name: "extract_entities", tokens: 847 });

// 3 — request judgment at a policy boundary
const decision = await nalvo.checkpoints.open(execution.id, { diff, impact: "low" });

// 4 — seal the record
await nalvo.executions.complete(execution.id, { output });
You do not have to adopt all of it at once

Sending executions and stages already creates a useful evidence history. Checkpoints, connection scopes and triggers can be added independently later.
