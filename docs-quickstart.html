Getting started

Quickstart

Ten minutes from an empty workspace to a complete execution record you can inspect stage by stage.

1 — Get an API key

Create a workspace, then open Settings → API keys and create one with the Read + write scope. The secret is shown once; store it in your secret manager.

shell
export NALVO_KEY="nlv_live_4f2a…c81d"

2 — Install the SDK

shell
npm install @nalvo/sdk       # node
	pip install nalvo-sdk        # python
	go get github.com/nalvo/sdk  # go

No SDK for your language? Everything here is a plain HTTPS call — see the REST API.

3 — Register the worker

A worker is a named, versioned definition of its model, allowed connections and policy boundaries. Keep it in your repository and deploy from CI, or create it in the workspace.

invoice-parser-v2.yaml
name: invoice-parser-v2
version: "1.0.0"
model: claude-opus-4
timeout: 1800
retries: 3

connections:
  - s3_upload
  - pdf_parser
  - slack_notify

boundaries:
  max_cost_per_execution: "$2.00"
  require_checkpoint_above: "$50000"
  pii_redaction: true
shell
nalvo deploy invoice-parser-v2.yaml
# → deployed invoice-parser-v2 v1.0.0 to production

4 — Open an execution and report stages

Wrap the work you already perform. Each stages.record call adds evidence to the execution history.

worker.js
import { Nalvo } from "@nalvo/sdk";
const nalvo = new Nalvo(process.env.NALVO_KEY);

const execution = await nalvo.executions.open({
  worker: "invoice-parser-v2",
  trigger: "schedule",
  input: { batch: "2024-08-03" }
});

try {
  const invoices = await nalvo.stage(execution, "extract_entities", async () => {
    return parseInvoices(input.batch);   // your code
  });

  await nalvo.stage(execution, "validate_schema", async () => validate(invoices));

  await nalvo.executions.complete(execution.id, { output: { parsed: invoices.length } });
} catch (err) {
  await nalvo.executions.fail(execution.id, { error: err.message });
}
nalvo.stage captures the evidence automatically

It times the block, records model and connection usage, and marks the stage failed if the block throws, keeping the record aligned with reality.

5 — Add a decision checkpoint

When an execution reaches a consequential action, request judgment. The call waits until a reviewer responds in the workspace or the timer escalates it.

worker.js
if (total > 50000) {
  const decision = await nalvo.checkpoints.open(execution.id, {
    title: "Review payment batch",
    impact: "medium",
    diff: { file: "batch-2024-08-03.csv", lines: changedLines },
    reviewers: "finance-ops",
    ttl: 14400            // escalate after 4h
  });

  if (decision.status !== "accepted") {
    await nalvo.executions.cancel(execution.id, { reason: "declined by " + decision.by });
    return;
  }
}

6 — Inspect the record

Open Live map. The execution appears after executions.open, stages arrive in real time and selecting the row unfolds the evidence. Human decisions arrive under Checkpoints.

WhereWhat you see
Live mapEvery active execution with its current stage
ExecutionsThe complete history without pagination
CheckpointsEvery action waiting for human judgment
InsightsSuccess, duration and spend by worker
